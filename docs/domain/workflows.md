# Flujos funcionales

Estado HEREDADO; condiciones pendientes en [preguntas](../decisions/open-questions.md).

## T1

Borrador → datos/contenido/actividades/matriz/anexos → previsualización → firma y finalización → revisión según grupo → validación/aprobación aplicable → ejecución.

La organización visual de pasos requiere reconciliación; conservar autorización e identidad durante todas las operaciones.

## Revisión

Asignación de etapa → artefacto exacto → observaciones generales o por zona → decisión. En paralelo, esperar todos los obligatorios. Devolver permite corregir; reenviar produce artefacto/ronda nuevos conservando firmas/decisiones previas como historia.

## Ejecución y T2

Plan validado → actividades visibles → responsables cargan evidencia por medio → revisor observa/valida → reemplazo permitido crea versión pendiente → Informe deriva datos del Plan → finalización/revisión según flujo T2.

## Estados

Separar documento, etapa y evidencia. Referencia documental: BORRADOR, FIRMADO_POR_ELABORADOR, EN_REVISION, DEVUELTO, EN_CORRECCION, VALIDADO, EN_EJECUCION, FINALIZADO. Evidencia: PENDIENTE_DE_VALIDACION, VALIDADA, OBSERVADA.

La tabla definitiva de transiciones, actores y precondiciones requiere validación antes del workflow. No establecer transición universal por comisión ni entender configuración como permiso ilimitado.
